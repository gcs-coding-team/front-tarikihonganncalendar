# 他力本願カレンダー — フロントエンド

プリントを撮ると、AI が予定とタスクに仕分けてくれる学生向けカレンダー。
`index.html` 一枚で動く。ビルド工程は無い。

## 動かす

### 端末内だけで動かす

`index.html` をブラウザで開くだけ。データは `localStorage` に入る。

### バックエンドと繋いで動かす

バックエンドは [gcs-coding-team/tarikihonganncalendar](https://github.com/gcs-coding-team/tarikihonganncalendar)。

```bash
# 1. API を起動（別リポジトリ側で）
go run .                       # :8080

# 2. フロントを同一オリジンで配信
node dev-server.js             # :3000
```

http://localhost:3000 を開く。設定タブに「接続中」と出れば繋がっている。

**同一オリジンで配信すること。** API は CORS ヘッダーを返さないので、別オリジンから
呼ぶとプリフライトが 401 で落ちる。`dev-server.js` は `/v1` と `/healthz` を API に
中継して同一オリジンに見せている。本番でも同じ形（リバースプロキシ）で置く。

## サーバーと端末の分担

| データ | 置き場 | 理由 |
|---|---|---|
| 予定 | サーバー | `/v1/events` |
| 時間割 | サーバー | `/v1/timetable-entries` |
| コロニー・共有 | サーバー | `/v1/colonies` |
| **タスク** | **端末内のみ** | API が無い |
| **プロジェクト** | **端末内のみ** | API が無い |
| 繰り返し予定の設定 | 端末内のみ | 予定に `repeat` を持たせる口が無い |

サーバーに繋がらないときは全部が端末内で動く。書き込みに失敗しても操作は止めず、
端末内の変更だけ残してその旨を知らせる。

## バックエンド側に足りていないもの

繋ぎ込みの過程で当たったもの。フロント側では回避してあるが、直せば素直になる。

1. **`/v1/tasks` と `/v1/projects` が無い** — タスクとプロジェクトが同期できない。
   端末を変えると消える。
2. **`GET /v1/colonies` が自分の作ったものしか返さない** — 参加しただけのコロニーが
   一覧に出てこない。フロントは覚えている ID を `GET /v1/colonies/{id}` で
   個別に引き直して補っている。
3. **招待コードからコロニーを引く口が無い** — `join` はコロニー ID を指定して呼ぶ作りだが、
   新規参加者はコードから ID を知る手段が無い。フロントは招待を
   `コロニーID-招待コード` の一続きの文字列として配ることで回避している。
   `POST /v1/colonies/join {inviteCode}` があれば要らなくなる。
4. **CORS が繋がっていない** — `middleware.CORS` は実装されているが、
   `cmd/api` 側にしか組み込まれていない。
5. **`shared-items` の `titleSnapshot` が捨てられる** — 送っても空で返る。
   共有フィードの見出しがサーバー側で持てない。
6. **予定に繰り返しの概念が無い** — `repeat` / `exdates` が端末内に留まるので、
   別の端末から見ると繰り返しが展開されない。
7. **ビルドが通らない** — `zatunohito/...` と `gcs-coding-team/...` の 2 つの
   import パスが混在し、`SessionRepository` と `AnalysisJobRepository` が
   二重に宣言されている。`cmd/api`（chi + Postgres）と ルートの `main.go`
   （net/http + インメモリ）の 2 系統が未統合のまま入っている。

`docs/api-spec.md` は実装より古い。`colonies` の join / members / feed は
「スタブ」と書かれているが実際は動く。
